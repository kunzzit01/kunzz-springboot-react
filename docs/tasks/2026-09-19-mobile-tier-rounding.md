## 现象（用户报）

100 PLUS 在手机版出了 52 罐；电脑「总库存」里那一层的数量变成 **-49**，总价 **-12.91**（倒扣）。

## 根因：手机版与电脑版的「价格层」不是同一个口径（真凭实据）

从**生产库 9/18 备份**（`manual_2026-09-18_1913.sql.gz`）里把 J1 的 100 PLUS 全部原始行拉出来，
按**原始单价**（5 位小数）分层是这样：

| 原始价 | 净数量 |
|---|---|
| 1.45000 | **-51** |
| 1.45410 | +54 |
| 1.45416 | 0 |
| 1.14280 | +56 |
| 1.14000 | -5 |
| 其它 | 0 |

而电脑版所有地方（「总库存」汇总、进出货页的价格下拉、出库库存校验）都是按
**显示价 ROUND(price,2) 分组**的（代码里写得很清楚：

- `StockSummaryMapper.xml`：`GROUP BY product_name, code_number, specification, ROUND(price, 2)`
- `StockEditMapper.xml` 的 `priceBatches`/`priceStock`：`GROUP BY ROUND(price, 2)`
- `StockInoutMapper.xml` 的 `availableStockCentral/Branch`：`AND ROUND(price, 2) = ROUND(#{price}, 2)`

所以电脑版看到的是两层：**1.45 → 3**（-51 + 54 + 0）和 **1.14 → 51**，合计 54。

但手机版的三个查询用的是**原始价**（`MobileStockMapper.xml`）：

```sql
GROUP BY COALESCE(price, 0), specification          -- tiersWithSpec / hifoTiers
CAST(COALESCE(price,0) AS DECIMAL(15,6)) = CAST(#{price} AS DECIMAL(15,6))   -- availableAtPrice
```

→ 手机看到的是「1.45 → 54」这一层（其实是 1.45410 那条），用户在手机上把剩余量改成 2、
手机按"价格从高到低"拆行时，从**它自己那一层**扣了 52（`deduct = min(remaining, 54)`），
写进台账就是 52 @ 1.45410。电脑再按显示价一分组：-51 + 54 - 52 = **-49** ✗。

一句话：**手机把一个电脑看不到的层当成可用库存**（那个层在电脑口径里只有 3），
出完就必然在电脑上表现为倒扣。这不是手机前端算错，是后端两个 mapper 的口径不一致。

## 改法（只改一个文件：MobileStockMapper.xml）

把手机侧四个查询的价格口径统一成 `ROUND(price, 2)`：

| 查询 | 用途 | 改动 |
|---|---|---|
| `tiersWithSpec` | 手机出货页读价格层 | `GROUP BY ROUND(COALESCE(price,0),2), specification`，`SELECT ROUND(...) AS price` |
| `hifoTiers` | 未指定价格时的自动拆行 | 同上（并保留 `HAVING available > 0` 与 `FOR UPDATE`） |
| `availableAtPrice` | 指定价格层的可用量预检 | `ROUND(COALESCE(price,0),2) = ROUND(#{price},2)`（与电脑端 `availableStockBranch` 完全一致） |
| `resolveInboundSpecForPrice` | 写入时取该价格层的规格 | 同样按 ROUND 比较 |

改完后的行为（以 100 PLUS 为例）：手机看到 **1.45 → 3**、**1.14 → 51**（与电脑一致），
用户把它改成 2（= 出货 52）时，手机自动拆成 **3 @ 1.45 + 49 @ 1.14**，
两层都落到 0 / 2，**不再有负数**；如果有人想直接在 1.45 这一层出 52，后端会拦下来（可用 3）。

分层看的价格仍然按规格拆（`+ specification`），因为「总库存」的行键是
产品+编号+**规格**+显示价，写入时规格必须落在同一个桶里，否则会多出一行。

4. 核对（应只剩 `1.14 → 2`，没有负数）：

   ```sql
   SELECT ROUND(price,2) AS disp_price,
          SUM(COALESCE(in_quantity,0)) - SUM(COALESCE(out_quantity,0)) AS net
   FROM j1stockedit_data
   WHERE product_name = '100 PLUS' AND deleted_at IS NULL
   GROUP BY ROUND(price,2) HAVING net <> 0 ORDER BY disp_price DESC;
   ```

## 已知边界（本次不动，先记录）

- 手机版**编辑**一条已存在的出货记录时，预检算的是"该层当前可用量"，没有把这条记录自己占用的量加回去，
  所以"把小数量改更小"也可能被提示库存不足（旧口径下同样存在，与本次改动无关）。
  修已产生负数那笔时请走"删除 + 重新录"，不要用编辑改数量。
- 台账里同一个显示价的多个原始价（1.45 / 1.4541 / 1.45416）仍然各存各的行，
  只是手机和电脑**都按显示价合并计算**了；没有做数据合并（那属于改历史数据，需要用户点头）。
