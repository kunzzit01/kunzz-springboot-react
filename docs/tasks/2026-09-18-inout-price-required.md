## 问题

用户在进出货页记一笔进货（数量 1），单价被自动填成 `0.00`，没注意就直接保存了 —— 总价 RM 0.00 静默入库，
库存**数量**对但**金额**被低估。查库确认存量问题不小：进货单价 0 的有 928 / 10,119 笔。

## 根因

不是校验缺失，两个刻意设计撞在一起：

1. 货品种类里 610 个货品的默认单价全是 NULL → `defaultPrice` 查询（只取 `price > 0`）永远返回 null；
2. 抓不到默认单价时，代码把单价输入框**填成字面量 `'0.00'`**（而不是留空），
   于是「单价不能为空」这道校验永远触发不了 —— 用户看到的是一格已经填好数字的输入框。

`0` 本身是**合法**单价（CHANGELOG 第 5 节：RM0 需记录，且 RM0 出货跳过库存校验），所以不能简单封 0，
要做的是把「没填」和「填了 0」区分开。

## 改动（4 处 + 1 处提示文字）

| 位置 | 现状 | 改为 |
|---|---|---|
| `StockInout.tsx:903` 选货品（新增行）| `dp !== null ? dp : '0.00'` | `dp !== null ? dp : ''` |
| `StockInout.tsx:949` 选编号（新增行）| 同上 | 同上 |
| `StockInout.tsx:1090` 改进货数量（新增行）| 同上 | 同上 |
| `StockInout.tsx:1042` 改进货数量（**编辑已有记录**）| 同上 | **抓不到默认单价就不动这一行现有的单价**（保留原值，不清空也不置 0）|
| `StockInout.tsx:1913` 单价输入框 placeholder | `"0.00"` | `"必填"`（灰色 0.00 会被误认为已填好）|

出货完全不动：赠品/损耗走「手动输入价格」，本来就要求手填，RM0 照旧能记。

后端不用改：`StockService.createInout` 已经拦 `price == null`，前端留空后天然会被它兜住。
